# Pindi Pie House

**Abdul Moiz** · Roll no. 24I2006 · Section C · CS4032 Web Programming, Assignment 02 (Fall 2026)

A React ordering site for a fictional pizza business serving students in Islamabad and Rawalpindi. Customers browse
the menu, search and filter, open a dish, build a cart, choose delivery or pickup, fill in a checkout form and reach a
simulated confirmation. It addresses three problems found on <https://www.pizzahutpakistan.com/> (see `DECISIONS.md`).

- GitHub: <https://github.com/abdul-m01z/pindi-pie-house>
- Deployment: <https://pindi-pie-house.vercel.app>

## Commands

```bash
npm install     # install dependencies
npm run dev     # development server
npm run build   # production build
npm test        # business-rule test (node --test)
```

## Routes

| Route | Purpose |
| --- | --- |
| `/` | Home: scroll-driven hero, popular dishes, hours, fees, delivery areas |
| `/menu` | 14 dishes with search, category and vegetarian filters, and sort (kept in the URL) |
| `/menu/:id` | Dish details, sizes, stock, price with GST, quantity. Unknown ids show a message |
| `/cart` | Quantities, delivery or pickup, area, full price breakdown |
| `/checkout` | Details form with validation, simulated order |
| `/confirmation` | Final summary |

## Operating rules

1. **Availability:** at most 6 of any one dish per order, and never more than today's stock (`src/rules/maxPerItem.js`).
2. **Order hours:** 12:00 PM to 11:30 PM, both included (`src/rules/orderHours.js`).
3. **Minimum delivery order:** PKR 800 of food before GST and fee; pickup has none (`src/rules/minimumOrder.js`).

`tests/minimumOrder.test.js` tests rule 3 with `node:test` (PKR 1,200 accepted, exactly PKR 800 accepted, PKR 799 rejected, pickup).

## Edge cases

Open "Demonstration controls" in the page footer.

| Case | How to reproduce |
| --- | --- |
| Loading failure | Tick "Make menu loading fail", then untick it and press "Try again" |
| Empty menu | Tick "Load an empty menu" |
| Missing images | Tick "Hide dish photos" |
| Sold-out or reduced stock in a saved cart | Add a dish, then sell it out, and open the cart. "Fix my cart automatically" repairs it |
| Order hours | Set "Pretend the time is" to 11:31 PM |
| No search results | `/menu?q=sushi` |
| Invalid URL | `/menu/nope` |
| Invalid form input | Submit the checkout empty, or enter phone `0300 123` |
| Cart kept on change | Switch between Delivery and Pickup with items in the cart |

## Simulated operations and limitations

- Orders, payment, delivery and the menu "network" are simulated. Names, phones and addresses are not stored.
- The cart, delivery choice and demonstration settings are saved in `localStorage`.
- The confirmation page is not saved: refreshing it shows "No recent order".
- Delivery areas are a fixed list, with no map or address check.
